# Персональный тайм-трекер на Java

Учебный проект по теме № 25 «Тайм-трекер (учёт рабочего времени)». Приложение предназначено для одного пользователя и хранит данные локально. Сетевой сервер, регистрация и облачная синхронизация не требуются.

## Технологии

- Java 17 — язык и целевая версия байткода;
- Maven — сборка, управление зависимостями и упаковка;
- Swing/AWT — графический интерфейс и системный трей;
- SQLite JDBC — локальное хранение категорий, задач, сеансов и пауз;
- OpenPDF — экспорт отчёта в PDF;
- JUnit 5 — тестовая зависимость для следующего этапа разработки (практическая работа № 4).

## Сборка и запуск

Установите JDK 17 или новее и Apache Maven 3.9 или новее. Из каталога `personal-time-tracker` выполните:

```bash
mvn clean package
java -jar target/personal-time-tracker.jar
```

Maven использует стандартные каталоги `src/main/java`, `src/main/resources` и `src/test/java`. Результат сборки помещается в `target/`. Плагин Maven Shade формирует исполняемый JAR с зависимостями и прописывает точку входа `ru.mirea.khusyainov.timetracker.App` в манифест.

Первый запуск создаёт локальную базу SQLite в каталоге пользователя:

- Windows: `%USERPROFILE%/.personal-time-tracker/tracker.db`;
- Linux/macOS: `~/.personal-time-tracker/tracker.db`.

Путь формируется через `user.home`, поэтому код не привязан к фиксированному диску или имени каталога Windows.

## Структура исходного кода

```text
src/main/java/ru/mirea/khusyainov/timetracker/
├── App.java
├── domain/
│   ├── model/                 # Category, Task, WorkSession, PauseRecord
│   └── repository/            # Контракты доступа к данным
├── application/
│   ├── task/                  # Сценарии работы с задачами
│   ├── timer/                 # Таймер, состояния и наблюдатели
│   ├── analytics/             # Стратегии рекомендаций
│   └── report/                # Экспорт отчётов и фабрики
├── infrastructure/
│   ├── persistence/           # SQLite и реализации репозиториев
│   └── platform/              # Адаптер системного трея
└── presentation/              # Главное окно и мини-панель
```

## Применённые паттерны

| Паттерн | Где используется | Зачем |
|---|---|---|
| State | `TimerService`, `TimerState`, состояния таймера | Запрет недопустимых переходов между состояниями |
| Observer | `TimerObserver`, `TimerService` | Обновление главного окна и мини-панели без прямой зависимости таймера от GUI |
| Strategy | `RecommendationStrategy` | Независимое добавление правил аналитики |
| Adapter | `DesktopIntegration`, `AwtDesktopIntegrationAdapter` | Изоляция системного трея и возможность fallback, если он недоступен |
| Factory Method | `ReportExporterFactory` | Создание экспортёра в зависимости от формата отчёта |

Дополнительно применяется Repository как архитектурный шаблон доступа к данным: прикладные сервисы зависят от интерфейсов репозиториев, а не от SQLite API.

## Важные ограничения текущей версии

Это промежуточная архитектурная версия для практической работы № 3. Она содержит базовый сценарий создания задачи и управления таймером. Полная аналитика, отчёты с фильтрами, история отчётов, восстановление незавершённого сеанса и расширенное тестовое покрытие будут развиваться в следующих практических работах. Наличие классов паттернов не означает, что все требования SRS уже реализованы.
